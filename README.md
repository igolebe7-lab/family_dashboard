# FamilyTime / Семейный Пульс

Приватная семейная PWA для календаря, дел, поручений, детских профилей, семейной ленты и in-app уведомлений.

## Репозиторий

Основной репозиторий: https://github.com/igolebe7-lab/family_dashboard.
Ветка `main` содержит актуальное проверенное состояние приложения. Дальнейшую
разработку ведём в этом же репозитории; завершённые изменения переносим в `main`.
Локальные базы PocketBase, пароли, `.env` и временные файлы проверок не публикуются.

## Текущий статус

Рабочее локальное приложение: регистрация семьи, приглашения взрослых, управляемые детские профили, Today, календарь, дела, поручения, поиск, уведомления и семейная лента. Расписание работы/секций создаётся как повторяющееся событие без отметки выполнения; дела и поручения могут повторяться с независимыми статусами.

## Целевой стек

- SvelteKit static SPA/PWA, TypeScript, Tailwind CSS;
- `@lucide/svelte` для иконок;
- GSAP только для точечных анимаций;
- PocketBase + SQLite + `pb_hooks`;
- Caddy для HTTPS, static frontend и reverse proxy к PocketBase.

## Запуск и проверки

```bash
pnpm install
pnpm dev
pnpm check
pnpm lint
pnpm test
pnpm build
```

Сначала запустите PocketBase (команда ниже), затем `pnpm dev`. Приложение доступно на `http://127.0.0.1:5173`. Установленный package manager: `pnpm@10.12.1`; альтернативный запуск: `npx pnpm@10.12.1 dev`.

По умолчанию API использует origin приложения. Dev и preview проксируют `/api` в PocketBase на `127.0.0.1:8090`. При необходимости адрес можно задать до сборки:

```bash
PUBLIC_POCKETBASE_URL=http://127.0.0.1:8090
```

В production используйте HTTPS и same-origin reverse proxy из Caddy. Переменные `PUBLIC_*` попадают во frontend: секреты в них хранить нельзя.

Локальный PocketBase после установки бинарника:

```bash
cd pocketbase
./pocketbase serve --http=127.0.0.1:8090 --automigrate=false
```

Бинарник PocketBase не должен коммититься в репозиторий.

## Проверка на чистой базе

`node scripts/smoke-backend-isolated.mjs` поднимает отдельный PocketBase на порту 8091 во временной директории, применяет миграции, выполняет проверки прав и бизнес-процессов и удаляет только собственную временную базу. Рабочая `pocketbase/pb_data` не используется.

Новые аккаунты регистрируются через `/register` и создают собственную семью. Второй взрослый открывает приглашение из раздела «Семья» и входит или регистрируется в контексте приглашения. Не используйте существующую демонстрационную семью для проверки onboarding.

## Статическая PWA

Повторы: будни, выбранные дни недели, ежедневные/ежемесячные, интервал и конечная дата. В подробностях события доступны перенос отдельной даты и архив; архивные записи находятся через фильтр «Архив» в поиске. Напоминания приходят в inbox, не через Web Push.

Дополнительные проверки:

```bash
node scripts/smoke-backend-isolated.mjs smoke-recurrence.mjs smoke-auth-profile-flow.mjs
node scripts/smoke-reminders-isolated.mjs
```

`pnpm build` создаёт `apps/web/build` с SPA fallback `200.html`. На сервере неизвестные frontend-маршруты должны возвращать этот файл; `/api` обрабатывается отдельно PocketBase.

`pnpm preview` проверяет именно статическую сборку на `http://127.0.0.1:4173`,
включая SPA fallback и service worker, с proxy `/api` на локальный PocketBase.
Этот Node-скрипт предназначен только для локальной проверки, не для production.

Service worker хранит только ресурсы приложения и статическую оболочку. Он не сохраняет API-ответы или URL приглашений. При потере сети показывается явное сообщение; полноценной offline-очереди изменений пока нет. В dev старый service worker автоматически отключается, чтобы исключить смешивание версий модулей.
