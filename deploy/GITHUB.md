# GitHub Actions: полная публикация FamilyTime

## Обычный процесс

1. Внести изменения в отдельной ветке, открыть PR в `main`, дождаться успешного
   `verify` на актуальной базе и слить PR. Прямой push запрещён и администратору;
   второй ревьюер не обязателен. Merge автоматически запускает публикацию.
2. Открыть GitHub → Actions → **FamilyTime CI and Deploy**.
3. Дождаться успешных `verify` и `deploy`. Ссылка приложения остаётся прежней.

Workflow запускается также вручную через **Run workflow**, только для main.
PR выполняет проверки без доступа к deployment secrets и без публикации.
Код сначала отправляется на GitHub, затем GitHub собирает именно этот commit.

## Что проверяется

Frontend check/lint/unit/build, Go race tests, изолированный backend smoke,
тесты приёмника. Собираются static web, Linux amd64 PocketBase, hooks и миграции.
Пакет хранится в Actions artifacts 7 дней. На VPS нет runner или сборки.

Перед переключением новый backend запускается на SQLite online-copy текущей
базы в отдельной systemd-службе: 180 MiB, 25% CPU, максимум 120 секунд,
без внешней сети, production-данных и секретов. Проверяются запуск, миграции,
SQLite integrity и foreign keys. Проверочный процесс работает отдельным
пользователем `familytime-check`, без прав пользователя рабочего backend на его
процессы и файлы. Файловое хранилище в preflight не копируется:
миграции, зависящие от физических вложений, требуют расширенного ручного испытания.

## Миграции

Все изменения `pocketbase/pb_migrations` относительно опубликованного commit
требуют подтверждения в environment **production-migrations**. Нажать
**Review deployments → Approve and deploy** после просмотра миграции и результатов CI.
Если текущий commit сервера неизвестен или недоступен, тоже требуется подтверждение.
Владелец может подтвердить свой запуск. Это намеренно строже автоматического
распознавания «безопасных» миграций: универсально доказать безопасность кода нельзя.
Frontend, Go-backend и hooks без изменений миграций публикуются автоматически.
Преобразования данных внутри Go/hooks тоже нужно оформлять явной миграцией,
а не обходить approval policy.

## Переключение и откат

Создаётся штатный backup. Затем под maintenance lock Caddy отвечает 503,
PocketBase останавливается и делается финальная копия базы, включая вложения.
Меняется current, запускается новый backend, проверяется локальный health.
Только после этого приложение снова открывается пользователям.
При ошибке до открытия возвращаются прежний релиз и финальная копия базы.
Повреждённая копия сохраняется в `/opt/familytime/failed-data-COMMIT` для разбора.
Если сам откат не удался, maintenance остаётся включён: нужна помощь администратора.

После открытия Actions проверяет публичные health и `/release.json`.
Ошибка внешней проверки НЕ откатывает базу автоматически: пользователи уже могли
внести новые данные. Нужна диагностика, а не потеря этих записей.
Отправленные внешние push нельзя отменить откатом базы.

Аварийное выключение VPS/kill -9 во время переключения не считается штатным
откатом. Проверить current, marker, rollback-data и journal; не удалять marker
до проверки согласованности базы и релиза. Повторный deploy того же commit
после его распаковки запрещён; для исправления нужен новый commit.

## Доступ и секреты

- Отдельный пользователь `familytime-deploy` и ключ в environment secrets.
- `DEPLOY_SSH_KEY`: закрытый ключ. `DEPLOY_KNOWN_HOSTS`: проверенный ключ сервера.
- Authorized key имеет forced command и `restrict`; shell/SFTP/forwarding недоступны.
- `/usr/local/sbin/familytime-deploy` и `/usr/local/lib/familytime/backup.sh` принадлежат root.
- Пакет не может заменить deploy tooling, Caddy, systemd или VPN.
- Код backend работает от `familytime`, а не root.
- Изменения приёмника и Caddy из git не применяются сами: их устанавливает администратор.
- Environments допускают только main. Не выдавать доступ на запись в main недоверенным лицам.

Для отключения: GitHub Actions → workflow → **Disable workflow**; для отзыва
доступа удалить deployment public key из `/home/familytime-deploy/.ssh/authorized_keys`.
Плановые backups/HTTPS и VPN продолжат работать.

## Ограничения

Краткий простой при backup и переключении; health не заменяет полный UI/e2e.
Деструктивные миграции требуют проверки смысла изменений человеком.
Архивы backup на VPS ограничены семью. Ежедневная очистка сохраняет current,
previous и три самых свежих релиза (объединение этих наборов).
Зашифрованные внешние копии хранятся на Mac; HTTP/TLS проверяются из GitHub и Mac.
Настройка и ограничения: [OPERATIONS.md](OPERATIONS.md).
После deploy установленной PWA может потребоваться подтверждение обновления.
